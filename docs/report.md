## 3. 해석

### 3.1 데이터 진단 (과제 2)
- **센서 기록 주기가 섞여 있다:** ⟨[02_diagnosis](../reports/02_diagnosis.md) 1장의 주기 표 요약⟩. 1차 기준선에서 실습실 온도·습도의 30분 오차가 15분보다 작게 나온 것(현재값 유지에서도 같음)은 모델이 아니라 이 기록 방식에서 온 현상으로 본다 ⟨진단서로 확인한 결과⟩.
- **결측:** ⟨긴 결측 구간과 추정 원인⟩
- **평일 패턴:** ⟨시간대별 CO₂ 그림을 글로 설명: 몇 시에 오르고 몇 시에 정점⟩
- **CO₂ 반응 시간:** 상승 시작부터 정점까지 중앙값 ⟨분⟩, 정점 뒤 절반 회복 ⟨분⟩ → 60분 예측과 30분 전 경보가 이 시간 안에 들어오는지.

### 3.2 예측 (과제 3)
- **무엇:** 5~60분 CO₂·온도 예측. **왜:** 1,000ppm 을 넘기 전에 환기 경보를 내려면 미리 알아야 한다.
- **어떻게:** 최근 2시간 입력, 지금 대비 변화량을 12칸 한 번에 출력, 공간 전체로 하나의 GRU. 현재값 유지가 가장 강한 기준선이라 그 위의 변화만 배우게 했다(절대값 예측은 버림).
- **결과:** ⟨공간별 수치⟩. 시각·요일 입력을 빼면 60분 CO₂ 오차가 사무실 +14.5, 실습실 +11.2, 회의실 +37.0 ppm 커졌다(1차 모델 기준). 일정 입력 효과: ⟨일정 포함/제외 차이⟩.
- **공간별 차이:** 회의실 오차가 가장 크다. 회의는 시작·종료가 불규칙하고 방이 작아 CO₂ 가 빨리 변하기 때문으로 본다 ⟨오차가 큰 시간대 근거⟩.

### 3.3 이상 탐지 (과제 4)
- ⟨규칙이 잘 잡는 고장(값 고정·끊김·급변)과 오토인코더가 잘 잡는 고장(잡음·드리프트)과 이유, 임계값-헛경보 곡선을 글로 설명, 운영 제안⟩

### 3.4 상태 추정 (과제 5)
- ⟨두 분류기 차이, 가장 많이 틀린 상황의 실제 모습, 서비스에 쓸 임계값⟩

### 3.5 사전학습 모델 채택 의견 (과제 6)
- ⟨정확도·구간·지연·메모리로 본 결론, 다음 주 로컬 LLM 과 같은 8GB 보드에 함께 올릴 수 있는지⟩

### 3.6 가장 의외였던 발견 (발표용)
- ⟨한 가지, 숫자와 함께⟩

## 5. 재사용성

- **설정만 바꾸면 된다:** 센서 형식 변경은 `configs/sensors.yaml`, 공간·임계값·공휴일은 `configs/default.yaml`, 정답 시간표는 `configs/schedule.yaml`.
- **학습과 서비스가 같은 코드:** 전처리 `preprocess.clean/to_wide`, 입력 `forecast.make_windows` 를 서비스도 그대로 쓴다. 모델 파일에 정규화 통계·공휴일·일정·보정 계수를 함께 저장한다.
- **모델 교체:** `.env` 의 `SERVICE_MODEL` 만 바꾸면 된다. 모델 파일이 없으면 기준선으로 계속 돈다.
- **검증:** pytest 38개 (합성 데이터로 수집 매핑, 전처리, 기준선, 예측, 이상 탐지, 상태 추정, ONNX 변환, 서비스 API).
- **재현:** `./scripts/run_all.sh` 한 번으로 과제 2~7 보고서 생성. 결과 형식은 [interface.md](interface.md).

## 6. 실패와 해결

### 6.1 GRU 가 현재값 유지보다 나빴다 (과제 3)
- **문제:** 1차 학습에서 60분 CO₂ 오차가 실습실 44.5, 사무실 46.4, 회의실 76.9 ppm 으로 같은 시점 현재값 유지(40.0, 46.4, 56.6)보다 나빴다. 회의실은 5분 오차부터 15.6 vs 10.4 ppm 으로 나빴다.
- **원인:** 검증 손실이 1번째 에폭에서 가장 낮고 학습 손실(0.131)보다 3배 이상 낮았다(0.037). 검증 기간(9/21~10/6)에 추석 연휴(9/24~26)와 개천절·대체공휴일(10/3, 10/5)이 몰려 방이 거의 비어 있었고, 조기 종료가 사실상 학습 전 모델을 골랐다. 또 '평일 여부' 입력이 공휴일을 평일로 보고 있었다.
- **해결:** 공휴일을 설정에 넣어 평일 여부에서 제외, 조기 종료는 검증 기간의 일하는 날 창으로만, 손실을 평가 지표와 같은 L1 로, 지평별 보정 계수 α(0=현재값 유지, 1=모델)를 검증에서 정해 최소한 기준선만큼은 나오게 했다. 결과: ⟨개선판 수치⟩.
- **재발 방지:** 검증·시험 기간을 정할 때 공휴일 목록을 먼저 확인하고, 학습 곡선에서 검증 손실이 학습 손실보다 훨씬 낮으면 기간 편향부터 의심한다.

### 6.2 값 고정 고장을 절반만 잡았다 (과제 4)
- **문제:** 합성 시험에서 3시간 같은 값을 넣었는데 값 고정 규칙 탐지율이 50%였다.
- **원인:** pandas rolling 표준편차는 긴 시계열에서 부동소수 누적 오차로 정확히 0 이 나오지 않는다.
- **해결:** '구간 최대 − 최소 == 0' 으로 판정을 바꿨다. 재발 방지: 같은 값 판정에는 분산 계산을 쓰지 않는다.

### 6.3 Jetson 에서 parquet 를 못 읽었다 (환경)
- **문제·원인:** 시스템 pandas 가 venv 의 최신 pyarrow 를 못 읽었고, 최신 pyarrow 는 NumPy 2 를 요구해 JetPack 의 OpenCV·TensorRT(NumPy 1.26 기준)와 충돌했다.
- **해결:** venv 에 pandas 와 `pyarrow<20` 을 설치하고 `numpy<2` 를 requirements 에 고정. 이후 모든 설치 명령에 `"numpy<2"` 를 함께 적는다.
